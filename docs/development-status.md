# 2.0 测试版开发与验证基线

更新日期：2026-10-15（Asia/Shanghai）。

当前 2.0 功能已接通；`versionName 2.0`、`versionCode 3`，数据库版本 3。产品构建与 199 项 JVM 测试通过，API 24 和 API 37 分别完整通过 124 项设备测试；API 37 合成端到端账本及实际 SAF 完整恢复经只读 SQL 核验通过。API 35 的全量长进程崩溃保留为验证限制，分段各项已有通过记录。

本次安装包与匹配源码入口为 [2.0 测试版发布页](https://github.com/le5676922-max/jizhang-qingji-app/releases/tag/v2.0-test)，对应标签 `v2.0-test`、资产 `qingji-v2.0.apk`。历史 `initial-public-snapshot` 仍是开发源码快照配较早 1.1 APK，并非从该标签构建的 2.0 包。

## 已接通范围

| 功能 | 当前实现 |
| --- | --- |
| 统一识别 | 通知、页面节点、自动本地 OCR、用户导入图片统一生成候选，事务内更新来源事件与账本；入库前和提交前检查配置／窗口是否仍有效。 |
| OCR 与采集边界 | 带位置的金额标签关联，全进程原生任务串行，节点深度／字数和图片像素上限；默认关闭、授权来源、敏感输入／安全窗口拒绝。 |
| 智能识别中心 | REVIEW 与正式账本分开；核对经济类型、方向、多金额、日期及分类；确认、关联、忽略、撤销忽略、撤销关联；回调校验来源指纹，旧编号复用不能误确认。 |
| 多来源匹配 | 同来源可靠共同订单可关联到同一账单；弱证据给人工建议，不以同金额永久合并；人工修改不被自动覆盖，删除／忽略保留身份历史。 |
| 经济用途与统计 | 消费、收入、转账、退款、还款；往来与还款不算新增消费／收入，退款关联原消费、检查剩余额度，按退款月份与原分类冲减净支出。 |
| 分类及回收站 | 手动与确认时可记住同来源商户的消费／收入分类；规则可删除；账单软删除、撤销删除及回收站恢复。 |
| 完整加密备份 | SAF 文件选择器、至少 8 字符且重复一致的新密码、PBKDF2 + AES-256-GCM、结构认证预览、二次确认覆盖、七张表及六项设置；失败检查点回滚及明确重试。 |
| 恢复安全 | 初始化／未完成恢复时禁止采集与修改；成功恢复后关闭通知、屏幕及自动 OCR，系统权限与旧启用时间不恢复。 |
| 旧账与导出 | 数据库 1／2 增量迁移，保留旧账与墓碑；旧待确认自动账生成 LEGACY 来源；CSV 原八列后增加“经济类型”和“关联原消费ID”，不是恢复文件。 |
| 设备能力与诊断 | 通用受限设置应用信息入口、后台运行设置入口，区分授权与实际连接；显示当前机型／API 的可用通道、低内存限制、通道耗时及来源事件数量。 |
| 自适应选项 | 账单筛选与编辑／核对选项使用 FlowRow，允许窄屏及大字体换行；主账单编辑器旋转时未保存草稿仍会丢失，见下方限制。 |

旧版没有的真实单号、经济用途或退款关联不从备注猜测。新 REVIEW 来源不创建第二笔待确认账单；兼容保留的旧人工待确认记录仍可编辑。旧自动待确认来源在识别中心核对，避免同时显示为另一笔新候选。

## Android 兼容边界

最低 Android 7.0／API 24，APK 包含 `armeabi-v7a`、`arm64-v8a`、`x86`、`x86_64`，未限定品牌。API 24–29 提供页面文字与手动图片识别，不能自动截屏；API 30–33 使用显示级截图并复核浮窗；API 34+ 使用目标窗口截图。Android 7–10 的 low-RAM 设备、工作资料夹及企业策略可能限制通知监听。

已验证的 API 35 x86_64 16 KB 本地模型和图形 JNI 能运行；第三方库 GNU_RELRO 末端的静态检查仍有疑点，不能由 ZIP 对齐或 x86_64 运行通过推断 ARM64 16 KB 手机也已通过。详见 [Android 兼容性](android-compatibility.md)。

**尚无真实三星 S23 Ultra、其他品牌、Android Go、无 GMS 实体手机、16 KB ARM64、折叠／副屏、真实微信／支付宝交易与当前页面版本的验收。** 支付应用无通知、无可读单笔结果页，或系统不允许截屏时，不能自动补出流水。主账单编辑器仍使用内存界面状态，Activity 重建会丢失未保存草稿，请先保存再旋转或折叠；已保存记录不受此限制影响。
