# V2 交易识别与核对规则

本项目的“智能”使用本地规则和离线中文文字识别，不调用聊天大模型。规则覆盖特定交易证据，不能代替支付平台的完整流水接口。

## 证据入口

| 渠道 | 获取条件 | 处理方式 |
| --- | --- | --- |
| 系统通知 | 用户开启通知访问、自动记录和对应来源；只接收启用之后的新支付服务通知 | 先验证包名及支付服务标题，再处理有界正文；通知更新保持原事件身份 |
| 无障碍节点 | 用户开启屏幕记账、系统服务连接、前台为微信或支付宝交易结果/详情页 | 先检查 Activity、标题元数据与敏感节点，再提取有界交易字段 |
| 自动截图 OCR | 节点不足、独立交易页已确认、额外开启截图识别，系统允许截图 | API 30–33 取显示截图并裁剪，API 34+ 取窗口截图；有其他窗口或安全限制时降级 |
| 导入图片 | 用户主动选择来源与图片 | 不要求自动来源开关开启；只形成待确认候选，不能凭导入直接计入统计 |

银行通知与短信尚未接入。聊天、普通交易列表、输入密码/验证码/金额页面、付款请求及不明布局不作为自动入账证据。没有系统通知且未打开可读取的单笔结果页时，应用无法得到交易金额。

## 决策与账本分离

`source_events` 保存来源证据和解释；`entries` 保存账本记录。V2 新产生的 `REVIEW` 候选不创建正式账目。旧版已有待确认行在迁移时保留，确认之前仍不参与统计。

- **AUTO**：完成状态、金额和方向明确，业务含义符合规则，有稳定事件身份且无未解决冲突。强订单关联只增加来源关联，不新增或覆盖账单。
- **REVIEW**：图片、OCR、弱身份、历史交易、多个金额、用途不明、转账/还款或来源冲突等情况。识别中心显示具体原因，用户可核对、更正、关联或忽略。
- **IGNORE**：已知失败、待支付或取消的证据不会入账；已删除或人工忽略的稳定订单也不会自动重建。无法形成合法交易字段的页面只更新诊断，不伪造金额候选。

自动入账不意味着系统保证整个支付账户的账单完整。金额采用整数分和严格十进制校验，拒绝三位小数、零值和越界金额。

## 资金方向与用途

| 业务类型 | 统计口径 | 核对要求 |
| --- | --- | --- |
| EXPENSE 消费支出 | 增加消费支出和原分类支出 | 明确已付款、转出且符合消费规则 |
| INCOME 收入 | 增加收入 | 不能仅因钱进入账户就推断为新增收入 |
| TRANSFER 转账 | 不计入消费或新增收入 | 确认用途；转给朋友消费可改为支出，自己账户间转移保留转账 |
| REPAYMENT 还款 | 不重复计入消费 | 本版不拆分本金与利息，也不是完整资产负债系统 |
| REFUND 退款 | 在退款发生月份抵扣原消费分类，不增加收入 | 关联已确认、未删除的原消费，累计有效退款不能超出原金额 |
| UNKNOWN 未确定 | 未确认前不参与统计 | 必须明确选择业务类型和资金方向 |

红包仅有“待领取”不证明已经扣款；明确已经发出并完成转出的红包才可按规则处理。转入、退款、内部钱包移动与消费不是同一种业务。

## 订单融合和撤销

同一事件的主指纹及别名持久化，编辑或删除后仍保留。订单号只保存提供方、命名空间和编号组合的 SHA-256；完整可读订单号不进入数据库。

强关联要求可信通知或节点证据，提供方、订单命名空间、稳定订单身份及金额/方向/业务类型一致，并对应已确认的正式账单。退款单号和原支付单号各有角色；同退款号却指向不同原支付的证据属于冲突。

金额、时间和商户接近只产生建议，不能作为永久唯一键。不同可靠单号的同金额付款保持独立。OCR 和导入图片即使识别到同一单号，也只提供人工核对。

人工关联或自动强关联可撤销，正式账单保持原样；撤销后的来源回到待确认。明确选择独立记录才能在存在重复风险时另外创建账单。删除账单保留来源和身份墓碑，可从回收站恢复。

## 金额区域和生命周期

OCR 保留临时行/元素坐标，将金额标签与相邻金额匹配，阻止跨越其他字段的绑定。余额、原价、优惠和手续费不会通过“取第一个金额”或“取最大金额”当成实付金额。实付区域仍有多个金额时，确认界面不预选实际金额。

节点最多遍历 200 个、深度 24；标题探测最多 24 个、深度 6。事件采用 650ms 防抖及合并队列；截图至少间隔 8 秒。全进程同一时刻只有一个原生 OCR 任务，图像长边最多 2048 像素、输出最多 300 万像素。

页面内容修订、窗口/包名/Activity、服务连接、来源配置和截图边界都参与结果有效性检查。关闭再开启来源不会让旧任务重新有效。页面切换、旋转或恢复账本后，旧结果不得写入当前账本。系统截图保护始终保留。

## 分类记忆

用户可选择记住提供方、规范化商户及资金方向对应的分类。规则只复用分类建议，不改变资金方向或用途，也不会把转账自动解释成消费。规则可在应用内删除。

## 验证边界

付款、转入/转出、红包、退款、多金额、重复、历史迁移、权限撤销和窗口失效均通过纯规则或隔离设备测试验证；具体已执行结果以 [验证记录](verification.md) 为准。合成测试的通过率不作为真实微信、支付宝或三星手机的识别准确率。真实版本的新布局需另行核对，未知布局保守降级。
