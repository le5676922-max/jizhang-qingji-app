# 隐私与采集边界

适用范围：当前 V2 工作树，更新于 2026-10-14。功能是否已在交付 APK 中验证，以该版本的构建、验证记录和版本号为准。GitHub 的首次源码快照与原 1.1 APK 不代表当前 V2 功能已完成验证。真实 S23 Ultra、微信和支付宝版本的页面覆盖仍需实机验证。

## 数据在本机处理

主应用移除了 `INTERNET` 和 `ACCESS_NETWORK_STATE` 权限，不提供账号、服务器、云 OCR、广告或分析上报。中文 OCR 使用捆绑的 ML Kit 模型，在设备端处理；模型为 `com.google.mlkit:text-recognition-chinese:16.0.1`。本项目只使用捆绑路径，没有调用按需下载模型或远程文字识别接口。[Google 官方集成说明](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)区分了捆绑与非捆绑模型。

不申请短信、通讯录、通话记录或读取整个相册的权限。通知访问和无障碍访问分别由用户在 Android 设置中授权；应用中的通知、屏幕和自动 OCR 开关默认关闭。微信、支付宝来源开关控制自动识别。用户主动选择来源并导入支付图片的单次处理不要求打开自动采集开关。

用户通过系统选择器导入图片、读取备份或导出 CSV / 加密备份。应用只处理本次选择的 URI，不遍历整个相册或文件目录。本次没有 `ACTION_SEND` 图片分享接收入口，`SHARED_IMAGE` 类型只是预留，不能通过其它应用的“分享至轻记”导入。用户选择的云盘等文档提供程序可能由其自身同步文件；轻记不会自行上传这些文件。

## 自动识别读取什么

通知通道只处理微信、支付宝的新支付服务通知，先检查来源、服务标题、开启时间和通知监听会话。它不回扫历史通知，不使用普通聊天标题作为付款证据，不保存完整通知标题、正文或通知 key。读取的正文暂存于有界内存队列，解析后持久化提取字段和哈希身份；满队列或存储失败会提示核对与手动补录。

屏幕通道先检查包名、前台窗口、Activity、服务连接、开关、配置版本、解锁与亮屏状态。已知聊天、付款输入、密码、验证码等 Activity 在读取控件文字前被拒绝。Activity 不明确时，只做有限的标题区域探测；无法确认独立交易结果或详情页身份时，不扩大为普通页面采集。

确认页面身份后先遍历控件元数据，拒绝密码框、可编辑框和系统标记的敏感控件，再保留与金额、交易状态、对方、交易时间或单号标签对应的有限文字。银行账号、卡号、手机号、聊天、备注、余额、优惠和商品字段不作为自动账本内容保存。采集有节点数量、深度、保留字数和频率上限；到达上限时放弃不完整观察。事件回调文字不被当作页面身份。

OCR 只用于通过门禁的交易页面，或用户主动选择的支付截图。它可以在内存中处理图片与识别原文，但不写入原图、裁剪图、OCR 原文或页面控件转储文件。解析得到的金额候选、经济类型等进入识别中心；图片识别须经人工核对后入账。用户自行填写的商家与备注属于用户账本数据，包含在导出和完整备份中。

## Android 版本与系统保护

| Android API | 当前采集方式 |
| --- | --- |
| 24–29 | 可读取系统允许的无障碍节点；不调用自动截图接口。用户仍可主动导入允许截图的支付图片。 |
| 30–33 | 可调用系统显示截图接口；在内存中按目标窗口边界裁剪，在截图、OCR 与入库前后重复检查其他窗口、页面与配置版本。发现重叠通知、浮窗、输入法或其它应用窗口会停止；该接口仍是显示级截图，不具备新版指定窗口截图的隔离保证。 |
| 34 及以上 | 使用指定无障碍窗口的截图接口，并检查事件及控件的 `isAccessibilityDataSensitive` 标记。 |

Android 的 [显示截图 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshot(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback)) 从 API 30 提供，[指定窗口截图 API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#takeScreenshotOfWindow(int,%20java.util.concurrent.Executor,%20android.accessibilityservice.AccessibilityService.TakeScreenshotCallback)) 和 [敏感节点标记](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo#isAccessibilityDataSensitive()) 从 API 34 提供。较早系统没有同等的敏感标记能力，因此仍使用页面身份、输入框和字段白名单的保守门禁。

API 30–33 的截图与窗口元数据查询不是原子操作。只在截图瞬间出现又消失、且窗口事件尚未送达的浮层仍可能无法检测，重复复核只能降低风险。自动OCR默认关闭；此类系统可保留节点识别，或主动导入用户选择的交易图片。原图和临时OCR文本不会持久化或上传。

应用不点击、不输入、不支付，不请求手势控制、Root、Xposed 或修改支付应用。系统隐藏节点、拒绝截图、限制授权或支付窗口使用 [FLAG_SECURE](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#FLAG_SECURE) 时，不尝试绕过。页面不可读时可手动记账。

## 关闭来源、撤销授权和中断

关闭通知、屏幕、OCR 或任一支付来源会递增识别配置版本。排队的通知、已抓取的窗口与进行中的 OCR 均绑定旧版本；切换窗口、服务断开或配置变化后，旧观察不能写入账本。入库事务结束前还会重新检查来源和观察是否有效。

截图硬件缓冲和 Bitmap 按生命周期关闭或回收。OCR 有全进程串行门禁；已进入 ML Kit 原生任务后会等待其完成再释放图片，即使调用协程已经取消，也不会提前回收仍被读取的 Bitmap。取消后得到的旧结果仍须通过窗口、连接与配置版本检查，不会因此重新开启采集。

恢复阻止状态用于停止采集及记账操作。启动时必须先处理任何未完成的恢复检查点，再发布账本状态；检查点损坏或回滚失败时，自动识别保持暂停，用户可显式重试恢复。服务连接或系统授权仍存在，不代表应用会越过这个暂停状态。

## 持久化数据范围

本机 SQLite 保存金额整数分、支出/收入方向、经济类型、分类、商家、用户备注、交易时间、来源、用户修改标记、退款原单关联和删除状态。来源事件还保存证据通道、规则版本、完成状态、固定核对理由、金额候选、哈希单号身份及账单关联；不保存单号原文。别名与已处理事件哈希用于避免重复和防止删除后自动复活。

商户分类规则、关联操作历史和有限的识别诊断也只保存在本机。诊断是固定状态、时间和耗时，不包含支付原文或截图。软删除账单、忽略记录和事件墓碑继续保留，以支持回收站、撤销及去重；删除单条账单不会立即销毁这些关联记录。

数据库和恢复检查点由 Android 应用私有目录隔离，当前没有对 SQLite 本身实施额外的数据库加密。恢复检查点包含覆盖前的完整提取字段快照，使用长度和 SHA-256 完整性校验；它没有使用用户备份密码加密，也不包含原截图、通知正文或 OCR 原文。检查点成功处理后删除。

系统云备份与设备迁移规则排除数据库、设置、私有文件及根目录，覆盖恢复检查点，Manifest 设置 `allowBackup=false`。Android 官方提示部分厂商的设备迁移可能不完全遵循单独的 `allowBackup` 开关，因此同时使用 [明确的数据排除规则](https://developer.android.com/guide/topics/data/autobackup#EnablingAutoBackup)。卸载或清除应用数据会删除本地账本与未完成的私有检查点。

## 用户备份与恢复

完整备份覆盖七张数据表及六项账本设置，包含软删除记录、旧待确认记录、来源候选、别名、永久去重墓碑、规则、关联历史和诊断。导出的 `.qjbackup` 使用随机盐、随机 nonce、PBKDF2 与 AES-256-GCM 认证加密；文件内容必须通过认证及严格结构、外键和退款金额校验才可恢复。密码不保存、不随备份写出，也没有密码找回功能。

格式对主键 / 外键设定 `2^53-1` 上界。故意构造恰在该上界的记录后继续新增，编号可能超出备份格式范围，导致完整导出及需要先保存原快照的恢复流程被拒绝。这不是正常真实账本规模会自然达到的状态；当前版本不承诺自动修复这种构造编号，校验失败会保留现有数据。

解密后先展示创建时间及账单、来源事件等数量，确认覆盖后才开始恢复。预览只持有私有明文副本，不暴露可变 JSON；取消或一次确认结束后销毁。错误消息不输出密码、明文、原 SQL 或私有文件路径。

恢复成功时只恢复预算与微信 / 支付宝来源选择，通知自动记账、屏幕识别和自动 OCR 均关闭，需用户重新开启。系统通知访问、无障碍权限、图片权限不从备份恢复；旧的自动记账启用时间也不导入。失败或进程中断时，使用私有检查点回滚原账本及原六项设置，原通知开关若开启则建立新的启用时间门槛。数据库、设置和检查点处理全部成功前，不报告恢复完成。

CSV 是普通可读的账本导出，未加密，也不是完整恢复文件。完整备份中的提取字段仍是财务数据；用户决定导出目的地、密码和文件保管方式。

## 覆盖与验证范围

无通知、没有打开可识别的独立支付页面、或系统没有提供节点 / 截图时，应用不能补出缺失流水。自动识别不等于完整银行账本；陌生布局、模糊金额、未知资金用途、历史时间和可能重复的证据需要核对。

项目没有逆向确认三星生活助手「我的账本」的内部采集机制。已有合成通知、原生节点、Canvas、受保护窗口和隔离数据库测试记录只证明对应夹具范围；不证明真实微信、支付宝或所有三星版本都受到支持。参阅 [源码调研](screen-research.md)、[架构](architecture.md)和具体交付版本的验证记录。
