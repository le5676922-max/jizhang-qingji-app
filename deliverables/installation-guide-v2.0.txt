1. 安装与升级
请确认文件名以 .apk 结尾；若变成 .apk.1，删除末尾 .1 后用系统文件管理器打开。
最低 Android 7.0（API 24），包含 arm64-v8a、armeabi-v7a、x86、x86_64 四种架构。
这是 Debug 签名测试版，与此前提供的 1.1 签名一致。升级前先备份；不要卸载或清除数据。
从源码自行构建通常使用自己的 Debug 密钥，签名不同不能覆盖本安装包。

2. 通知记账
在“自动记账”中授予通知访问，再开启“自动记录收支”，选择微信／支付宝来源。
只处理启用后新到达的支付服务通知，普通聊天消息不作为支付凭据。
微信转账、红包可能没有系统通知，请使用交易详情页识别或主动导入截图。

3. 屏幕记账
打开“识别交易结果页”，阅读用途说明后在系统无障碍设置启用“轻记 · 屏幕记账”。
三星若提示“由受限设置控制”：设置→应用→轻记→右上角菜单→允许受限设置，按系统提示确认。
其它品牌设置名称可能不同；应用提供通用应用信息及“管理后台运行”入口。
返回轻记确认“已连接”；“已授权，等待系统连接”不等于采集已开始。
付款后打开单笔成功页／交易详情并停留片刻。聊天、金额输入、密码页和普通账单列表不作为入口。

4. 系统能力分级
Android 7–10：交易页文字识别、主动导入截图、手动记账；不支持自动截图。
Android 11–13：可尝试显示级截图 OCR；输入法、浮窗或其它应用窗口可能暂停识别。
Android 14 及以上：可尝试指定交易窗口截图；系统敏感内容与受保护页面仍无法保证识别。
本地 OCR 单独开启，至少间隔 8 秒，模型随 APK 捆绑，无需云端识别。
低内存 Android 7–10 设备可能不支持系统通知监听；请查看应用中的本机兼容提示。

5. 为什么有些记录仍需确认
可靠、无冲突的完成消费可自动入账。转账、还款、OCR、历史或缺少稳定身份的结果需核对用途。
转账／还款不重复计入消费或新增收入；退款须关联原消费，累计退款不能超过原消费。
识别中心里的待确认来源不增加统计。同一订单的多个来源可关联同一账单，避免重复。
无法获取通知、读取结果页或截取安全窗口时，可手动补录。

6. 备份与已知限制
“自动记账”底部可创建完整加密 .qjbackup 文件；密码至少 8 字符，无法找回。
恢复先验证密码及预览，再确认覆盖。成功恢复后通知、屏幕与自动 OCR 开关关闭，需重新开启。
CSV 是明文导出，不能代替完整加密备份。
Android 7.0／API 24 与 API 37 专用模拟器均通过完整 124 项测试，另有合成端到端验证；未认证所有品牌真机。
16KB x86_64 环境的 OCR／图形 JNI 与分组测试有通过记录，但长套件曾出现 ART/JIT 崩溃，原因未定。
ARM64 16KB、真实 S23 Ultra、当前微信／支付宝布局及各品牌后台策略仍需真机验证。
编辑账目时旋转／折叠导致界面重建，未保存草稿可能丢失；已保存账目保留。
