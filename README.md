# 轻记 · Android 本地自动记账

当前源码为 **2.0 测试版**（`versionName 2.0`、`versionCode 3`）。通知、页面文字、本地 OCR、识别中心与完整备份恢复已接通；产品构建和 **199 项 JVM 单元测试**已通过。API 24 与 API 37 的 **124 项设备测试分别全量通过**，合成通知、页面节点与 OCR 的端到端账本及实际 SAF 完整恢复核验通过。API 35／16 KB 分段各项通过，长进程崩溃限制见验证报告。

安装包与匹配源码入口为 [2.0 测试版发布页](https://github.com/le5676922-max/jizhang-qingji-app/releases/tag/v2.0-test)，对应标签 `v2.0-test`、资产 `qingji-v2.0.apk`。此前 `initial-public-snapshot` 保存的是开发快照，随附 1.1 APK 与本次 2.0 不同。当前验证状态见 [开发状态](docs/development-status.md)。

应用使用 Kotlin、Jetpack Compose、Material 3 和本机 SQLite。最低 Android 7.0（API 24），打包四种 CPU ABI，不限定手机品牌；根据系统能力提供通知、页面文字或截图识别。自动截图需要 Android 11（API 30）以上；中文 OCR 模型捆绑在应用内，无需账号或云识别服务。三星 S23 Ultra 满足 API 要求，但真实手机、当前微信和支付宝页面覆盖尚未验证；不能将模拟器通过写成“所有型号均已适配”。

## 2.0 已接通的功能

- **三个识别入口**：微信、支付宝的新支付服务通知；已打开的单笔交易结果／详情页文字；符合安全条件的本地 OCR。也可主动导入支付截图，图片候选必须确认后入账。
- **智能识别中心**：来源事件与正式账单分开。待确认不增加统计；可核对类型、方向、实际金额、日期和分类，确认新账单、关联已有账单、忽略、恢复待确认及撤销关联。已关联的冲突凭据确认时会明确提示修改已有账单。
- **经济类型与统计**：区分消费支出、收入、转账、退款、还款。转账与还款不重复计入消费或新增收入；退款关联原消费，在退款发生月份抵扣净支出，并沿用原消费分类。
- **分类记忆与溯源**：可记住同一来源、同一商户的收入／消费分类，并查看、删除规则。账单保留来源、证据渠道与人工修改标记，自动识别不会覆盖人工修改。
- **可恢复账本**：手动补录与编辑、月度预算、分类统计、搜索、软删除、删除后撤销及回收站恢复。新候选不再保存为第二笔待确认账单。
- **完整加密备份**：通过系统文件选择器导出 `.qjbackup`，使用 PBKDF2 与 AES-256-GCM 认证加密。包含账单、已删除记录、识别来源、去重身份、关联历史、分类规则和设置。验证密码及完整性、展示预览，再二次确认覆盖；恢复失败保留原账本回滚检查点。
- **旧账迁移与 CSV**：数据库 1／2 升级保留旧账及已处理身份，不猜测旧转账用途。CSV 在原八列后增加“经济类型”和“关联原消费ID”；CSV 只用于可读导出，不提供完整恢复。
- **设备能力与布局**：显示当前设备的系统能力、低内存通知限制和后台设置入口；按 Android 7–10、11–13、14 以上分级启用截图功能。筛选与核对选项允许窄屏、大字体换行。

微信转账或发红包可能只有应用内消息，没有金额系统通知。此时需要打开可读取的单笔交易结果／详情页，或主动导入允许截图的凭据；无通知、无可读结果页时不能补出流水。

## 安装与系统权限设置

从发布页下载 `qingji-v2.0.apk`。文件名必须以 `.apk` 结尾；若下载后变成 `.apk.1`，先删除末尾 `.1`，再通过系统文件管理器打开，并按系统提示允许该来源安装。旧账会随数据库升级迁移；卸载或清除应用数据会删除本机账本，请先保留导出或备份。

1. 打开轻记的「自动记账」→「屏幕记账」，开启「识别交易结果页」，阅读并同意用途说明。
2. 若显示「由受限设置控制」，通过应用提供的「打开轻记应用信息」入口进入系统应用信息，允许受限设置，再授权服务。三星常见路径是 **设置 → 应用 → 轻记 → 右上角 ⋮ → 允许受限设置**；其他品牌的名称和位置可能不同。该选项是否显示取决于系统版本与安装来源，应用不能自行解除限制。
3. 再进入系统 **辅助功能／无障碍 → 已安装的应用 → 轻记 · 屏幕记账**，启用服务。
4. 返回轻记确认显示 **「已连接」**。「已授权，等待系统连接」只说明权限已授予，不能据此判断采集已开始；可重开服务并检查后台限制。
5. 保留所需微信／支付宝来源开关。转账或发红包后，打开成功页、转账详情或红包详情并停留片刻。聊天、输入金额、密码页、普通账单列表和未知布局不会作为自动截图入口。
6. 按需开启「结果页截图识别」。自动 OCR 至少间隔 8 秒；系统与支付应用决定能否截图。Android 7–10 可读页面文字和手动导入，不能自动截屏。
7. 无法自动识别时，选择「导入支付截图识别」和支付来源；到「查看待确认账单」进入智能识别中心核对。多个金额必须明确选择实际交易金额；安全页面不能截图时请手动记账。

通知记账独立开启：允许「通知访问」，再打开「自动记录收支」。只处理启用后收到的新支付服务通知，不回扫历史；普通聊天通知不会作为付款凭据。自动记账页还显示各通道最近成功／失败、耗时和来源事件数量，可先判断授权、连接及采集状态。

「设备兼容性」显示当前系统可用通道，并提供「管理后台运行」入口。厂商省电、强制停止或企业管理可能中断服务；应用不能替代系统授权。Android 7–10 的 low-RAM／Android Go 设备可能无法绑定通知监听器，可使用页面文字或手动记账。能力矩阵、16 KB 原生库核查及运行范围见 [Android 兼容性](docs/android-compatibility.md)。

## 核对与统计规则

**资金转出不一定是消费，资金转入不一定是收入。** 给朋友转账、钱包之间转移、还款需要核对经济用途。转账／还款、未知用途、OCR／导入图片、历史凭据、无稳定身份、多金额或可能重复的结果进入识别中心；未确认来源不计入正式账本。

同一来源的可靠订单身份可关联多个证据到一笔账单。缺少可靠共同单号时只给人工核对建议；不同单号的同金额交易保持独立，金额相同不能作为永久合并依据。忽略、删除与撤销关联保留身份记录，避免自动重新入账。

退款只能关联已确认的原消费，累计退款不能超过原消费金额。分类抵扣归原消费；跨月退款在退款月份冲减净支出，该月净支出可能为负数。旧版“退款”分类收入不会仅凭分类名自动改成关联退款，需用户核对。

待付款、失败、取消或只有「待领取」而无已发出／扣款证据不能直接入账。支付页面不是稳定开放接口：系统可能隐藏敏感节点，`FLAG_SECURE` 窗口不能截图。本项目不绕过限制，也不承诺完整银行流水覆盖。

## 本地数据与备份

主 App 不声明 `INTERNET` 或 `ACCESS_NETWORK_STATE` 权限，不上传账本、原图或识别文字。无障碍只读取所选支付来源，不点击、不输入、不支付；用户可关闭开关或撤销系统授权。截图和 OCR 原文仅在有界内存中使用；持久化提取字段、金额候选、固定说明和哈希身份，不保存完整通知、页面转储、单号原文或图片。

完整备份的新密码至少 8 个字符，需重复输入一致；密码不保存、无法找回。预览或取消不修改账本，确认恢复才替换。恢复成功保留预算及支付来源选择，**通知、屏幕及自动 OCR 三个开关关闭**；系统权限不从备份恢复。初始化或恢复失败时，采集与修改暂停，可明确重试。

本机 SQLite 本身未额外加密；系统备份关闭。恢复检查点在应用私有目录保存覆盖前提取字段快照，用于失败回滚，处理完成后删除。CSV 是普通明文导出，不能代替完整加密备份。预算是全局月度额度。详细边界见 [隐私说明](docs/privacy.md) 和 [数据架构](docs/architecture.md)。
